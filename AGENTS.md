# Architecture
- Mount reading progress at the shared layout level so case studies and same-origin snippet frames measure their own document; keep sticky-bar offsets in CSS tokens.
- Use shared image-loading observation and asset dimensions to reserve existing image ratios without duplicating image renderers or changing loaded artwork.

- Origin Markets keeps a dedicated overview and shared project data, with lazy-loaded secondary content available only inside snippets; this preserves its distinct layout without standalone secondary pages.
- Case-study closing copy uses optional outcome-closing and reflection-subtitle fields in the shared renderer so additional supplied copy does not require duplicate layouts.
- Desktop case-study sections share a narrow title rail and wider gutter; section-level grids place the first non-empty content beside the title so empty introductions cannot create alignment gaps.
- Scope Origin overview presentation under `.origin-editorial`; its editorial layouts must not change shared case-study or portfolio styling.
- Other case studies use `.case-study-editorial` with existing narrative sections and shared typography tokens; this extends the Origin template without altering portfolio cards or requiring research sections on simpler projects.
- Cross-project image pointers are re-uploaded to this project and paired with local optimised images so the portfolio also works on GitHub Pages.
- Origin sample-work uploads use CDN pointers with local optimised fallbacks and explicit image dimensions so static hosting and lazy-loaded layouts remain stable.
- Mendeley Library, Reader and Citation use separate shared snippet cards and lazy-loaded modal content selected by URL, without a tab menu; legacy detail links retain their selected content.
- Case-study closing navigation uses shared ProjectPagination and portfolio order, honouring each project's custom destination; this keeps previous/next links consistent with the listing.
- Define portfolio groups in shared project data and derive the combined navigation order from them so listing sections and case-study pagination stay aligned.
- Share anchor alignment through `scrollToSection`, loading only preceding images and cancelling pending work on navigation; this keeps saved links and rapid tab clicks stable without eagerly loading entire case studies.
- Use React state directly for this static portfolio; no query provider is needed without remote data requests.
- All secondary case studies use the shared snippet dialog and destination registry, with same-origin frames on parent case-study URLs and top breadcrumbs; legacy secondary URLs redirect to parent pages with their modal open, preserving content, tabs and shared links without standalone pages.
- Every enabled snippet renders dedicated content with a shared SnippetHeader and case-study section typography; design-system modals must not render a filtered section of the parent case study, so each story can evolve independently.
- Portfolio and case-study snippet cards share one card component and content registry; this keeps images, titles, descriptions and availability consistent across entry points.
- Scope MDS QuoStar screenshot rows with `mds-image-row`; wrapping flex rows centre incomplete groups without changing other case-study galleries.
- Cybermon infographic styling is scoped under `.cm-page` with per-year colours via `.cm-year[data-year]`, and subsections pick their layout from a `variant` field in the page data; this keeps the playful treatment off other case studies.
- Case-study cards on every page render the shared `CardBody` from project-grid; style changes then apply everywhere at once.
- Home and portfolio cards share `ProjectCardMedia`, retaining their own link destinations and media classes so consolidation cannot change presentation or navigation.
- Mendeley Reader and Citation share `MendeleySections`; their lazy-loaded pages are snippet-only, with the Reader introduction excluded from its first section to avoid repeating it.
- Tailwind colour aliases read global CSS tokens, including opacity modifiers, so palette updates have one authority without changing font stacks or rendered colours.
- Case-study card artwork uses an optional `cardImage` separate from `heroImage`, with CDN pointers and local optimised fallbacks, so uploaded covers do not alter case-study content or static hosting.
- GitHub Pages deploy runs scripts/mirror-assets.mjs after build to copy every .asset.json image into dist; static hosting cannot serve Lovable CDN paths.
- Share reduced-motion subscriptions and reference-count header measurement per document so links, layout and section navigation do not install duplicate browser listeners or observers.
- Verify secondary content inside its same-origin snippet frame, not the parent dialog DOM, to avoid false missing-content diagnoses during changes.
